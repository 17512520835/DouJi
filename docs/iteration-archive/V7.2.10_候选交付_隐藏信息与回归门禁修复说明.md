# V7.2.10 候选交付：隐藏信息与回归门禁修复

本候选只处理封箱前两项阻断，不改角色数值、地图规则、ResponseWindow、移动、缩域或美术。

## 1. 高手 AI 隐藏信息隔离

`v7210OpponentAwareInternalChoice()` 不再直接以完整内部 GameState 作为搜索树根。新增 `v7210PerspectiveState(state, rootSide)`：

- root AI 自己的当前手牌保留（属于自身已知信息）；
- 对手真实手牌身份在进入 lookahead 前替换为惰性未知牌占位，不携带真实牌名/类型/能力；
- 双方牌库顺序在进入 lookahead 前替换为惰性未知牌占位；
- 后续 `simGetLegalActions()` 只在这个信息集搜索状态上执行，因此 opponent actual hand 不再决定对手具体隐藏牌响应分支。

Phase 1 不引入未知手牌概率模型；未知牌不会被伪装成已知具体牌。

新增门禁：`v7.2.10_high_ai_hidden_information_regression.js`。它同时检查生产/Debug bundle 的隔离结构，并执行 8 组、最多 240 次高手 AI 决策的只读性/合法性回归。

## 2. 封箱回归基础设施

- `v7.2.6_phase5_long_ai_stability.js`：废弃 phase-stuck 计数，改为 State Digest stagnation；当前快速门禁 4 局、每局最多 700 action。
- `v7.2_map_phase2_regression.js`：迁移到 `engine.v721.core.bundle.js`。
- `v7.2_map_phase2_public_api_fuzz.js`：迁移到 `engine.v721.core.bundle.js`；快速门禁为 8 Seed × 最多 80 action。
- `v7.2_map_fayoum_regression.js`：迁移到当前 bundle，不再依赖临时 engine.v720 alias。
- `v7.1_combat_regression.js`：不再依赖缺失的 `engine.v702.core.bundle.js`，改为当前等价 Engine Core + ResponseWindow 兼容门禁。
- `v6.6_signature_playability.js`：不再依赖缺失历史内部 API，迁移为当前公共 Core 的九角色可玩性/AI 合法性门禁。
- 新增 `run_all_regressions.js`，用于一键执行当前候选的正式自动门禁。

## 3. 本候选不宣称的事项

浏览器真实人工体验仍需最终人工门禁；30～50 Seed 扩展长局建议作为下一轮最终封箱压力测试，而不是用快速 CI 门禁替代。
