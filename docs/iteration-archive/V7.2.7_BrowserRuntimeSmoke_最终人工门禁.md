# V7.2.7 Browser Runtime Smoke — 最终人工门禁

当前验证机的 Chromium 被组织策略限制正常 URL 导航，因此项目代码无法、也不应该绕过管理员策略。

Phase6 新增 `v7.2.7_browser_runtime_smoke_server.py`，用于在**正常、未被 URLBlocklist 限制的 Chrome/Chromium** 环境一键启动正式入口。

验收步骤：

1. 运行 `python v7.2.7_browser_runtime_smoke_server.py`。
2. 使用正常 Chrome/Chromium 打开脚本输出的 `http://127.0.0.1:8765/...` 正式入口。
3. 确认角色选择页正常显示。
4. 选择双方角色并进入战斗。
5. 确认地图 Canvas、双方角色状态、手牌、Buff/持续状态、战报均正常显示。
6. 执行至少一个合法卡牌/技能/移动动作。
7. 进入一次 ResponseWindow（可用实机操作触发）。
8. DevTools Console 必须无未处理 JS Error。
9. Network 中 `engine.v721.core.bundle.js` 与 `frontend.engine-adapter.v721.js` 必须 200。
10. 完成后记录为 `Browser URL Entry Runtime = PASS`。

注意：当前交付包内已有静态入口 PASS 与 Chromium JS/DOM 运行诊断证据，但**在受管理员策略限制的验证机上不得伪写正式 URL Runtime PASS**。
