# V7.0.2 设计审计与调整报告

## 审计结论

V7.0.1 的“最多一次主动权转移”应继续冻结。它带来的主要收益是限制状态空间，而不是宣称两次转移会无限循环。第二次转移仍是有界机制，但当前没有足够的实测收益证明值得增加状态、UI、AI 与回归组合。

## 已采纳

- 修复文档中“一次 / 两次主动权转移”的直接冲突。
- 写死主动权计数参数语义。
- 补全反击完整结算、反攻期间挣脱、返回主行动段的边界。
- 将 `roundFirstPlayer` 作为正式名，同时保留兼容字段。
- 将僵直反馈从“测试手工模拟事件”升级为真实引擎事件。
- 明确账本已有汇总缓存，避免重复工程。
- 补充惊险挣脱的设计定位。

## 暂不采纳

- `maxInitiativeTransfers` 改为 2。
- 新增 `maxCounterAttacks`。
- 修改惊险挣脱成功阈值、支付或失败惩罚。
- 删除 `roundOwner`。
- 在无性能剖析证据时建立全量二级索引。

## 后续实测指标

建议 V7.1 收集：首击被反攻率、原攻链/反攻链平均与 P90 长度、反攻后胜率变化、惊险挣脱各角色基础与中盘成功率、使用后期望生命损失、结构化账本查询在 AI 搜索中的耗时占比。
