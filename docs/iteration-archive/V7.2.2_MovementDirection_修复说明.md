# V7.2.2 MovementDirection 移动方向一致性修复

本修复针对实机发现的两类问题：

1. 某些牌/人物技能进入移动选择时，没有展示 Core 真正允许的全部方向；
2. 已经点选某个方向/落点后，结算或动画却没有沿玩家选择的方向执行。

## 根因

- UI 过去会对部分移动重新调用 `getReachableMovePaths()` 自己构造目标，而不是直接使用 `simGetLegalActions()` 返回的具体动作，因此 UI 与 Core 有机会出现方向集合不一致。
- `evade` 闪避反击尤其明显：UI 会让玩家选移动格，但 Core 的 `fxEvade()` 完全忽略 `movePath`，转而自动执行 `RETREAT`，所以会出现“明明选了 A 方向，角色却往 B 方向退”的现象。
- 多步移动动画此前只从起点向最终落点做直线插值，遇到绕障碍/转折路径时，视觉上会像穿墙或朝错误方向移动。

## 修复

- 玩家可选移动统一以 Core legal action 为事实源；
- 卡牌按 `cardInstanceId` 优先匹配，不再仅按牌名折叠；
- 技能移动按 `skillId + legal movePath` 提交；
- 闪避类反击新增 `retreatOnly` 合法落点集合，并由 Core 严格校验；
- 选择哪个闪避后退格，就执行哪个 `movePath`；
- 无合法后退格时，闪避仍能成立，但不发生位移；
- 多步选定路径按每一格逐段播放动画，视觉轨迹与实际 path 一致。
