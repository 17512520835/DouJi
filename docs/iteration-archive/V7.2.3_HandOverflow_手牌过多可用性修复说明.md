# V7.2.3 HandOverflow 手牌过多可用性修复

## 根因

本问题不是 Core 把“第 6 张以后”的牌判成非法牌。生产 Core 的 `getLegalActions()` 对 `p.hand` 使用完整 `filter` 枚举，并没有 `slice`、固定 5 张上限或超量手牌截断。

真正故障发生在浏览器 UI：手牌卡固定宽度约 190px，手牌区使用 `overflow-x:auto`，但整页 `body` 又是 `overflow:hidden`。当手牌变多后，后半段卡牌被放到横向溢出区域。桌面鼠标普通滚轮产生的是纵向 `deltaY`，原 UI 没有把它转换为横向滚动，也没有左右浏览按钮；在部分系统滚动条默认隐藏时，玩家看起来就像“手牌太多以后后面的牌无法使用”。

此外 `renderHand()` 每次重建整段 DOM，原实现没有显式保存横向位置，这会放大超量手牌的操作困难。

## 修复

- 手牌区新增明确的左右浏览按钮。
- 鼠标普通滚轮在手牌区自动转为横向浏览。
- 支持键盘 ← / → / Home / End。
- 保留触摸横向滑动。
- `renderHand()` 重绘后恢复原来的横向位置。
- 左右按钮会根据是否还能继续滚动自动禁用。
- 不修改卡牌费用、手牌上限、抽牌、角色数值、连击、MovementResolver 或 MapState 规则。

## 验证

新增 `v7.2.3_hand_overflow_ui_regression.js`，验证浏览按钮、滚轮映射、滚动位置恢复、键盘访问，以及 Core 的合法牌枚举仍然覆盖完整手牌。
