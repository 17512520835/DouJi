# V7.1.3 ResponseWindow / 地图稳定性修复说明

本版只处理本轮确认的问题，不重构惊险挣脱 / EXPANSION_END 的历史时序。

## 1. 地图尺寸为什么会变化

V7.1.2 将 `#responseContext` 放在 `#battleScreen` 顶层，而 `#battleScreen` 只定义了三行 Grid。响应横幅显示时，它成为额外的第 4 个网格子项并生成隐式行，直接压缩 `.battle-main`，所以地图进入 / 离开 RESPONSE_WINDOW 时会缩放。

**修复：** 将响应横幅移动到 `.board-panel` 内，并改为绝对定位覆盖层。显示和隐藏不再参与战斗主布局计算，地图尺寸由 board panel 独立决定。

## 2. 常驻 Buff / 状态栏为什么“代码有但玩家看不到”

V7.1.2 确实加入了 `publicStateNames()`，但状态 chips 位于 fighter 内容最底部；fighter 使用 `overflow:hidden`，响应横幅又会压低中部高度，因此状态区域很容易被裁掉。

**修复：**
- 每名角色左侧信息区固定保留“持续状态”栏；
- 状态栏固定在角色卡底部可视区域，并横向滚动，不再被普通内容挤出；
- 层数统一显示，例如 `进化羽 ×3`、`命运 ×2`、`护盾 ×2`、`中毒 ×2`；
- 同时纳入姿态、控制、持续、瞬时追击状态；
- 补充可公开的机制状态：荣耀回刺就绪、守中藏针就绪、天际鸣啸强化、追步层数、冠军怒吼加成、湖舞层数等；
- 无状态时明确显示“无持续状态”。

## 3. RESPONSE_WINDOW 多段追击专项验证

新增 `v7.1.3_response_window_multihit_regression.js`，构造 4 段连续攻击而不是只测单次窗口。

专项覆盖：
- 第 1～4 击逐击进入 RESPONSE_WINDOW；
- 第 2 / 3 / 4 击分别执行普通挣脱；
- 第 2 / 3 / 4 击分别执行反击；
- 第 2 / 3 / 4 击分别执行放弃响应；
- 每次检查 pendingCard 是否清理、相位是否正确、chain step 是否保持正确、Core invariant 是否成立。

当前专项结果：**10 / 10 PASS**。

## 4. “我正在响应什么”

响应覆盖层继续显示：
- 攻击者 → 防守者；
- 当前攻击牌名；
- 第 N 连击；
- 起手 / 追击；
- 追击条件。

复合追击条件不再显示 `[object Object]`，而会按“或 / 且 / 非”转换为可读文本。

## 5. 本轮明确没有改的内容

Core 中“惊险挣脱 / EXPANSION_END”的旧时序仍然保留。它与本轮地图布局、状态可见性和 WeakMap / ResponseWindow 问题不是同一故障源。

本轮先确认普通响应链稳定；该历史时序应在后续独立版本中清理，避免把规则重构与响应热修混在一起。
