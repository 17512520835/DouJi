# V7.2 MovementResolver 统一移动修复说明

本轮针对 V7.2 Map Core 审计中剩余的三项结构风险完成收口：**自动移动与主动移动执行器不统一、自动移动对 `edge.cost` 的语义不一致、Occupancy 仍偏双人特化**。

## 1. 统一 MovementResolver

生产 Core 新增统一 `MovementResolver`，移动模式为：

- `VOLUNTARY`：玩家主动选路、战术步、游步、技能选路；
- `APPROACH`：自动接近、突进；
- `RETREAT`：自动后退；
- `FORCED`：击退等强制位移；
- `TELEPORT`：预留瞬移语义；
- `SHRINK_RELOCATE`：缩域强制迁移。

除开局出生点初始化外，生产 Core 中角色位置的运行时修改已经收口到 MovementResolver 内部路径执行/迁移执行，不再由 `moveToward()`、`moveAway()`、战术步、绝技突进等各自直接写 `player.pos`。

## 2. 移动力与 edge.cost 统一

`VOLUNTARY / APPROACH / RETREAT` 统一把数字解释为**移动力预算**：

- 普通边 `cost=1`；
- 困难边 `cost=2`；
- 预算不足时不能穿越；
- `end_move`、泥地、浅水仍会终止本次移动。

因此“自动向目标移动2”与“主动获得2点移动力”现在共享同一套 cost 语义，不再存在自动移动按两次 step 绕过困难边 cost 的偏差。

`FORCED` 刻意保留“击退 N 格”的位移距离语义：它仍由统一 Resolver 处理边、Occupancy、封锁和终止地形，但困难边的 `cost` 只记录为 `terrainCost`，**不会把击退1格变成需要2点移动力**。这是 movementMode 的规则差异，而不是另一套执行器。

`SHRINK_RELOCATE / TELEPORT` 不消耗路径移动力，但目标格仍必须合法且未被占据。

## 3. Occupancy 通用化

新增统一 `canEnterCell()` / `occupiedCellLabels()`：

- 直接读取当前 `players[].pos`，避免兼容镜像过期导致重叠；
- 同时读取 `MapState.occupants`；
- 预留 `MapState.entities`，其中 `blocksMovement !== false` 的实体会阻止进入。

主动选路、自动接近、自动后退、强制位移、缩域迁移现在都通过同一 Occupancy 入口检查，不再以 `next === opponent.pos` 作为唯一占位规则。

## 4. 一并消除的旁路

本轮还把此前仍可绕开统一移动语义的入口收口：

- 战术步“只传方向、不传 movePath”的分支现在也检查移动力 cost；
- 游影【疾影二段】/【轻身回气】选路进入 MovementResolver；
- 游步进入 MovementResolver；
- 绝技突进进入 `APPROACH` 模式并产生正常位置/距离领域事件；
- 赤羽击退追步进入 `APPROACH` 模式；
- 缩域迁移进入 `SHRINK_RELOCATE` 模式。

## 5. 回归结论

新增 `v7.2_movement_resolver_regression.js`，覆盖：

1. cost=2 边不能用1点移动力穿越；
2. 自动接近按移动力预算，而非按 step 次数；
3. 自动后退同样遵守 edge cost；
4. 通用地图实体 Occupancy 会阻止进入；
5. 强制位移走统一 Resolver，同时保持“击退 N 格”的距离语义；
6. 战术步方向分支不能绕过困难边 cost。

本轮实际结果：**6/6 PASS，exit code 0**。
