## 1. V7.0.2 · 设计审计与调整

**承接：** 自 V6.6 起的 81 局 / 810 局 harness 验证后，做一次系统性"我们到底在做什么"的盘点。

**做了什么：**
- 把 9 个角色的核心循环拆成 8 类机制清单（出牌 / 移动 / 攻击 / 追击 / 反击 / 挣脱 / PendingChoice / 缩域）
- 识别"机制交叉"的灰色地带（如反击中的 PendingChoice）

**解锁了什么：** 给 V7.1.1 Engine Core 化提供了**机制清单**——否则没办法决定"哪些规则应该进 Core"。

**PM 价值：** 决策前先盘点，是项目统筹的基本动作。

**对应文档：** `docs/iteration-archive/v7.0.2_设计审计与调整报告.md`

## 2. V7.1.1 Engine Core Phase 1–4 · 架构封箱

### Phase 1（首版 Engine 化）
- 目标：把规则核心从 HTML 里抽离到独立 JS 模块
- 关键决策：**生产引擎** vs **debug 引擎**分离。生产只暴露 `window.GameEngine` Facade，debug 暴露内部函数
- 验证：保持旧单文件 HTML 作为 Golden Master

### Phase 2
- 收窄 UI 兼容层；扩大 ExpansionLedger 作为事实源；删除 turn 的规则读取回退

### Phase 3
- 物理删除展开历史 mechanics 镜像；把攻击 / 卡牌 / 治疗 / 移动 / 受伤相关规则分支统一收口到 ExpansionLedger
- 跑 9 角色签名回归：`v7.2_stage3_nine_role_signature_regression.js`

### Phase 4（封箱）
- 6 条停止条件（详见 `docs/05-架构契约.md` § 6）：
  1. Production UI cannot mutate rules except through Core commands
  2. Hidden information only exits through Observation
  3. Expansion history has one authoritative Ledger
  4. Replay(config + seed + commands) reproduces digest
  5. Random legal sequences preserve invariants
  6. Golden Masters remain preserved
- 修复了 Fuzz 发现的一个封箱 bug：拉封骑士 / 骑枪总冲在 PRE_ATTACK 直接进入 CHASE_WINDOW 但未建立 expansion

**PM 价值：** Phase 1–4 不是一气呵成，是**阶段性封箱**——每个 Phase 都先验证上一 Phase 的所有承诺再往前走。

**对应文档：** `docs/iteration-archive/V7.1.1_EngineCore_Phase4_架构契约.md`

## 3. V7.1.3 · ResponseWindow 地图稳定版

**承接：** Engine Core 化后，UI 改造响应窗口时改变了地图尺寸，导致响应信息丢失。

**做了什么：**
- RESPONSE_WINDOW 横幅不再改变地图尺寸
- 左侧双方角色信息区固定显示持续 Buff / 状态与层数
- 响应信息显示攻击者、牌名、第 N 连击与追击条件
- 新增第 2/3/4 连击的反击、普通挣脱、放弃响应专项回归

**未在本轮重构：** 惊险挣脱 / EXPANSION_END 历史时序（明确推迟，避免本轮 scope creep）

**PM 价值：** 主动声明"未在本轮重构"是进度管控的反模式防御——不把所有"该做的"塞进同一个版本。

## 4. V7.2.1–V7.2.4 · 机制修复（4 个小版本）

| 版本 | 修复对象 | 现象 | 根因 |
|------|---------|------|------|
| V7.2.1 | 障碍 / 高差可视化 | 地图上的高低差地形看不出来 | 渲染层没读地图数据 |
| V7.2.2 | 移动方向一致性 | 玩家选了"左前方"实际走"右前方" | 三套路径解析各自偏移 |
| V7.2.3 | 手牌过多可用性 | 8+ 张手牌时点击查看详情失败 | UI 列表渲染假设最多 7 张 |
| V7.2.4 | 被动摸牌软上限 | 长局手牌堆积到 12+ | 主动 / 被动摸牌共用硬上限 |

**PM 价值：** 4 个版本节奏稳定可预测——每个版本**只修一类问题**，便于回归测试。

## 5. V7.2.5–V7.2.6 · 地图重构

### Phase 4 缩域专项（V7.2.5）
- 规则：每 3 回合地图边界缩一圈，到第 12 回合只剩中央
- 修复：法尤姆缩域机制的多角色兼容问题

### Phase 5 长局稳定性（V7.2.6）
- 12/12 自然结束、0 COMMAND_REJECTED、0 Event duplicate、0 Snapshot pollution、0 Replay digest mismatch
- Browser URL Entry Runtime 因当前验证机 Chromium 策略阻断，**明确标 PENDING**——不伪报 PASS

**PM 价值：** V7.2.6 是项目里**最有代表性的一次进度管控**——遇到环境阻断不糊弄，如实标记 PENDING。

## 6. V7.2.7 Phase 6 · 最终封箱

**核心动作：跨版本 Golden Master 比对**

| 项 | 内容 |
|---|------|
| **选基线** | `engine.v714.core.bundle.js`（v7.1 稳定基线）vs `engine.v721.core.bundle.js`（v7.2 当前生产） |
| **方法** | 固定 Seed + 双方角色 + 先手；每一步从两个版本共同合法动作中选择同一个语义动作；执行后比较玩家可观察 Digest |
| **结果** | 场景 16 / command 163 / 完全一致 12 / 已批准差异 4 / 无法解释差异 0 |
| **已批准差异** | 仅包含 V7.2.4 囚徒被动摸牌 Soft Target + 法尤姆【太阳算式】真实 PendingChoice 修复——这两项是已知有意变更 |
| **结论** | Observable Golden Master PASS。无未知玩家可观察回归 |

**PM 价值：** 跨版本比对是**对前面所有工作的最终验证**——不是单版本自洽，是跨版本一致。

**对应文档：** `docs/iteration-archive/V7.2.7_Phase6_最终封箱说明.md`

## 7. V7.2.8 · 纯美术优化

**原则：** 不改任何游戏逻辑，只改美术。

**意义：** 证明前面的 Engine Core 封箱有效——纯美术变更不影响逻辑，所以不需要重跑全量回归。

## 8. V7.2.9 · 死手与可用牌修复

**问题：** 某些极端局面下，玩家手牌里"全部不可用"但仍有手牌——UI 没有"放弃本回合"按钮。

**修复：** 增加"放弃"按钮 + 死手判定。

## 9. V7.2.10 Online Phase 1 · 联机交付

| 子项 | 内容 |
|------|------|
| **联机服务器** | Node.js HTTP + 自研 WebSocket，权威服务器架构，0 npm 依赖 |
| **Online 客户端** | `src/online.html`（17KB，与单文件版共享 Core） |
| **战斗通报** | Online UI 订阅 Core Event Ledger（攻击 / 追击 / 技能 / 绝技 / 展开推进） |
| **囚徒回血修正** | V7.0 时代遗留下来的"标准角色回血量"过强问题，借本轮一并修复 |
| **打击反馈** | CSS/DOM 视觉层（短促位移 / 柔和闪光 / 浮字），不阻塞 Core 结算 |
| **可访问性** | 支持 prefers-reduced-motion |

**PM 价值：** Online Phase 1 是"项目最后一公里"——前面的所有 PM 工作在这里变现为可远程联机的产品。

**对应文档：** `docs/iteration-archive/V7.2.10_战斗通报与囚徒回血修正说明.md`、`docs/iteration-archive/ONLINE_请先阅读.md`
