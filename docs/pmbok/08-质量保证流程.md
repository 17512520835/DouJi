# 08 · 质量保证流程

## 1. 质量体系概览

本项目采用 **三层质量防线 + 一双态门禁** 的策略：

```
第一层：回归测试（自动化）
  ├── 24 个 JS 回归脚本（每版本/阶段一份）
  ├── 22 份 JSON 验证报告（机器可读）
  └── 1 键全量：node run_all_regressions.js

第二层：状态三态门禁（半自动化）
  ├── PASS  → 放行
  ├── FAIL  → 阻断（必须修复后再尝试）
  ├── WARN  → legacy 版本白名单降级（记录但放行）
  └── PENDING → 环境阻断（不伪报 PASS，如实标注）

第三层：跨版本比对（封箱审计）
  └── Phase 6 Golden Master：同一 Seed 跨 v714/v721 双版本比对
```

## 2. 回归测试矩阵

|---------|--------|---------|

| 高手 AI | 3 | AI Phase 1 + 隐藏信息 + 长局 |
| Online 联机 | 2 | 端到端 + 协议 |
| **合计** | **24** | — |

## 3. 状态三态门禁规则

| 状态 | 定义 | 示例 |
|------|------|------|
| **PASS** | 用例通过 | 移动方向修复后 `v7.2.2_movement_direction_regression.js` PASS |
| **FAIL** | 代码 bug 或回归 | Phase 4 Fuzz 发现拉封骑士/骑枪总冲 bug |
| **WARN** | legacy 版本允许的精确白名单降级 | V7.2 Phase 3 九角色签名回归中 3 个旧版本断言 WARN |
| **PENDING** | 环境阻断，不是代码问题 | V7.2.6 Browser URL Entry Runtime 因 Chromium 策略无法执行 |

**禁止：**
- ❌ 把 PENDING 标 PASS
- ❌ 把 WARN 标 PASS
- ❌ 用"反正别人跑也会遇到"掩盖 FAIL

## 4. 质量 KPI

| KPI | 目标 | 实际 | 数据来源 |

| 联机协议正确性 | 通过 | ✅ | `online_protocol_regression.js` |

## 5. 质量改进闭环

```
发现问题（对局回放/用户反馈）
       ↓
  写回归脚本（确保不再回归）
       ↓
  跑全量回归（验证修复未引入新问题）
       ↓
  PASS → 发布 / FAIL → 回炉
       ↓
  写迭代说明 MD（现象→根因→修复→验证）
       ↓
  归档到 docs/iteration-archive/
```
