# 05 · 风险管理计划

## 1. 风险登记册

| 编号 | 风险 | 概率 | 影响 | 等级 | 策略 | 应对措施 |
|------|------|------|------|------|------|---------|
| R1 | Engine Core 迁移工作量低估 | 高 | 高 | 🔴高 | **减轻** | 4 Phase 分步封箱，每 Phase 独立验证 |
| R2 | 旧代码回归（迁移引入新 Bug） | 中 | 高 | 🟠中高 | **减轻** | 每 Phase 重跑全套回归 + Phase 6 跨版本比对 |
| R3 | 长局稳定性不足 | 中 | 中 | 🟡中 | **减轻** | Phase 5 专项长局验证，12/12 自然结束 |
| R4 | 隐藏信息泄漏 | 低 | 高 | 🟠中高 | **减轻** | Observation 边界强制 + Phase 4 封箱 + High AI 专项验证 |
| R5 | Online 架构选型错误 | 中 | 中 | 🟡中 | **减轻** | 锁步模拟 vs 权威服务器对比分析 |
| R6 | 单人项目倦怠 | 中 | 中 | 🟡中 | **接受** | 小步快跑、每 Phase 有可交付物 |
| R7 | Browser 环境兼容性 | 中 | 低 | 🟢低 | **接受** | 标注 PENDING，不影响功能可用性 |
| R8 | 部署平台不兼容 | 低 | 中 | 🟢低 | **规避** | 零依赖设计（0 npm/0 框架），纯 Node.js 内置模块 |

## 2. 实际发生过的风险事件

| 事件 | 关联风险 | 实际结果 |
|------|---------|---------|
| | **R1 · Engine Core 工作量低估** | |
| 老代码耦合度高，Phase 1–3 每阶段迁完后发现新依赖 | R1 | 延长至 Phase 4，但未牺牲质量 |
| 拉封骑士/骑枪总冲在 PRE_ATTACK 直接进入 CHASE_WINDOW 未建立 expansion | R2 | Phase 4 Fuzz 发现并修复 |
| | **R3 · 长局稳定性** | |
| 被动摸牌把手牌堆到 12+ 张 | R3 | V7.2.4 用软目标替代硬上限 |
| | **R4 · 隐藏信息泄漏** | |
| 高手 AI 对手隐藏手牌旁路 | R4 | V7.2.10 候选交付修复 |
| | **R7 · Browser 兼容性** | |
| 验证机 Chromium 策略阻断 URL Entry | R7 | 标注 PENDING，不伪报 PASS |

## 4. 后备计划

| 场景 | 触发条件 | 应对 |
|------|---------|------|
| 无法找到公网 IP | 家里 CGNAT | ChmlFrp / NATAPP 隧道穿透 |
| Node.js 环境不可用 | 部署节点异常 | 回退到 React SPA + Vercel |
| 朋友无法访问 IP | 防火墙未放行 | 一键开放防火墙 .bat |
| Online 协议需要升级 | 需求变化 | 沿用现有 WebSocket 协议，不引入新框架 |
