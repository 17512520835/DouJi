## 2. 需求来源追溯

本项目 12 个版本的需求全部来源于以下三类，**不凭空添加功能**：

### P0 级 —— 真实对局阻断性 Bug

| 案例 | 版本 | 现象 |
|------|------|------|
| 移动方向结算不一致 | V7.2.2 | 玩家选了"左前方"，引擎结算到"右前方" |
| 拉封骑士/骑枪总冲提前进入 CHASE_WINDOW | V7.1.1 Phase 4 Fuzz | 绝技需要追击时未先建立 expansion |

### P1 级 —— 实测发现但未阻断

| 案例 | 版本 | 现象 |
|------|------|------|
| 手牌超过 8 张无法查看详情 | V7.2.3 | UI 渲染假设最多 7 张 |
| 长局被动摸牌把手牌堆到 12+ | V7.2.4 | 主动/被动摸牌共用硬上限逻辑 |
| 地图高低差无法识别 | V7.2.1 | 渲染层没读地图数据 |

### P2 级 —— 架构性长期投资

| 案例 | 版本 | 目标 |
|------|------|------|
| Engine Core 化 | V7.1.1 Phase 1–4 | 规则核心与 UI 分离 |
| MovementResolver 统一 | V7.2 MovementResolver | 所有移动路径解析收口到一个模块 |
| Online 联机 | V7.2.10 | 浏览器 0 安装远程对战 |

## 3. 需求优先级矩阵

```
              │ 高频出现
    P0 阻断   │ ■ V7.2.2 移动方向
    ──────────┤ ■ V7.1.1 Fuzz bug
    P1 体验   │ ■ V7.2.3 手牌过多
              │ ■ V7.2.4 被动摸牌
              │ ■ V7.2.1 地形可视化
    ──────────┤
    P2 架构   │ ■ V7.1.1 Engine Core
              │ ■ MovementResolver
              └──────────────→ 影响面 → 大
```

**决策原则：P0 > P1 > P2；同一优先级按"先修复冷门角色特殊交互"排序。**

## 4. 需求进入版本的典型流程

```
对局回放/朋友反馈
       ↓
  现场复现 + 根因分析（写入 MD 的"现象/根因"段）
       ↓
  分类：P0 阻断 / P1 体验 / P2 架构
       ↓
  P0 → 下一 hotfix        P1 → 阶段收尾附带      P2 → 独立 Phase
       ↓
  实现 → 写回归脚本 → 跑回归拿 PASS → 写 MD 说明
```
