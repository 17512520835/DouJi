# 07 · 技术实施方案（联机平台）

## 1. 方案概述

在 V7.2.10 Online Phase 1 中为《斗鸡》实现浏览器端 2 人远程实时联机。采用**权威服务器（Authoritative Server）架构**，不采用锁步模拟（Lockstep Simulation）。

## 2. 架构选型分析

### 备选方案对比

| 维度 | 权威服务器 ✅ 选择 | 锁步模拟 ❌ 放弃 |
|------|-------------------|-----------------|
| **隐藏信息安全** | 手牌/牌堆仅服务端持有，客户端只收本方 Observation | 双方各自运行完整引擎，存在手牌泄漏风险 |
| **防作弊** | 客户端无法伪造状态（服务端是唯一权威源） | 客户端持有全部状态，易被修改 |
| **带宽** | 仅传输动作（每条几十字节） | 同样仅传输动作 |
| **部署复杂度** | 需要一台 Node.js 服务器 | 无需服务器（P2P直连） |
| **延迟容忍度** | 高（回合制天然不敏感） | 高 |
| **断线恢复** | 凭 resume token 重连 | 需重新同步整局状态 |
| **Core 加载** | 服务端加载一次 386KB Core | 双方前端各加载一次 386KB Core |

**决策理由：** 隐藏信息安全 + 防作弊 > 部署开销。386KB 前端加载在 WebRTC 场景下可接受，但在锁步模式中首次同步会成为瓶颈。

## 3. 技术架构

```
┌─────────────────────────────────────────────────────────┐
│  客户端 A（online.html）                                    │
│  - 渲染 UI（手牌区 / 地图 / 英雄 / 卡牌详情）                    │
│  - 只接收本方 Observation                                │
│  - 只能提交本方合法动作                                   │
│  - ws://<server>/ws 连接服务器                           │
└────────────────────┬────────────────────────────────────┘
                     │ dispatch(command)
                     │ getObservationForSide(side)
                     ▼
┌─────────────────────────────────────────────────────────┐
│  权威服务器（online-server.js · Node.js）                    │
│  - 持有唯一真实 GameState（所有状态/手牌/牌堆均在服务端）      │
│  - engine.v721.core.bundle.js（确定性引擎实例）              │
│  - 仅下发本方 Observation + 公开事件                       │
│  - 房间管理（创建/加入/断线恢复）                           │
│  - 自研 WebSocket 协议（0 npm 依赖）                       │
│  - 端口：8787 · 绑定：0.0.0.0                            │
└────────────────────┬────────────────────────────────────┘
                     │ dispatch(command)
                     │ getObservationForSide(side)
                     ▼
┌─────────────────────────────────────────────────────────┐
│  客户端 B（online.html）                                    │
│  - 同客户端 A                                             │
│  - 不同 side 的 Observation 分别下发                       │
└─────────────────────────────────────────────────────────┘
```

## 4. 关键组件说明

### 4.1 联机服务器（online-server.js）

| 属性 | 值 |
|------|-----|
| 语言 | JavaScript（Node.js） |
| 代码量 | ~200 行 |
| 外部依赖 | **0** npm 包（纯 Node.js 内置模块：http + crypto） |
| WebSocket | 自研实现（基于 Node.js http upgrade） |
| 环境变量 | `PORT`（默认 8787）· `HOST`（默认 0.0.0.0） |
| 健康检查 | `GET /health` → 200 OK |
| 静态文件 | 托管 `online.html` 等（`no-store` 不缓存） |

### 4.2 客户端（online.html）

| 属性 | 值 |
|------|-----|
| 代码量 | ~17KB（纯内联 HTML+CSS+JS） |
| 连接方式 | `ws://<server-ip>:8787/ws` |
| 连接逻辑 | `location.host` 自动解析 → 支持 file:// 兜底输入 |
| 断线恢复 | `resume token` + `roomId` 存 localStorage → 服务器未重启可重连 |
| 邀请码 | 6 位大写字母房间码 |

### 4.3 通信协议

**动作消息格式：**
```json
{
  "type": "action",
  "roomId": "ABC123",
  "token": "xxx",
  "command": { "kind": "play_card", "cardName": "太阳算式" }
}
```

**Observation 下发格式：**
```json
{
  "type": "state",
  "observation": { /* 只含本方 hand + 对方 handCount */ },
  "events": [ /* delta only */ ]
}
```

## 5. 部署方案

| 方案 | 适用场景 | 成本 | 步骤 |
|------|---------|------|------|
| **局域网直连** | 两人同一 Wi-Fi | ¥0 | 主机双击 `启动联机服务器.bat` → 朋友用 IP:8787 加入 |
| **内网穿透** | 异地（无公网 IP） | ¥0 | ChmlFrp/NATAPP 隧道转发到本地 8787 |
| **Railway 部署** | 异地（稳定） | ¥0 额度 | 通过 Git 仓库自动部署 |
| **腾讯云轻量** | 国内低延迟长期 | ¥40–60/月 | 上传文件 → `node online-server.js` |

详细部署步骤见 `../07-部署与发行.md`。
