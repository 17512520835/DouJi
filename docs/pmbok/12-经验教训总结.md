# 12 · 经验教训总结

> 本文档汇总本项目从 V7.0.2 到 V7.2.10 全程积累的项目管理经验与反思。条目按"保留（继续做）→ 改进（下次改）→ 停止（不再做）→ 开始（新做）"四象限排列。

## 1. 保留（Continue）

### ✅ 阶段性封箱（Incremental Closure）
**做法：** 每个 Phase 在开启下一 Phase 之前先验证上一 Phase 的承诺仍成立。Phase 4 封箱后增加 Phase 6 Golden Master 比对。

**效果：** Phase 4 → v714 → Phase 6 → v721 跨版本比对时，没有发现一例无法解释的玩家可观察回归。

**结论：** 阶段性封箱是单人项目最有价值的质量策略。继续。

### ✅ 回归测试当门禁（Regression as Gate）
**做法：** 任何修复/变更都必须通过相关回归脚本，且在有条件时跑全量。

**效果：** 22 份 JSON 验证报告构成可机读证据链；任何人可以重现。

**结论：** 回归门禁不能省。继续。建议下一项目把门禁写成可执行脚本（`gate_check.js`），不靠人工判定。

### ✅ 如实标注 PENDING（Honest Status）
**做法：** Browser URL Entry Runtime 因 Chromium 策略无法执行时，不归咎环境，如实标注 PENDING。

**效果：** 作品集透明度得到保证；面试时不需要"解释"一个本来就不存在的 PASS。

**结论：** 如实标注 PENDING 是 PM 诚信的基本素养。继续。

### ✅ AI 边界声明（AI Boundary Disclosure）
**做法：** 在 `docs/06-AI辅助边界声明.md` 中明确列出 AI 参与和未参与的范围。

**效果：** 面试时可以直接引用这份声明，避免"是不是 AI 全做的"质疑。

**结论：** 对 AI 辅助项目来说，边界声明从 Day 1 就要写。继续。

## 2. 改进（Improve）

### 🔶 Engine Core 迁移应先冻结老代码
**当时的错误：** 老代码边迁边改，回滚成本高。Phase 1–3 每阶段都"觉得差不多了"就往前走，结果 Phase 4 必须做 fuzz 才发现一个封箱 bug。

**改进方向：** 下一项目第一步先 freeze 老代码 → 新代码平行开发 → harness 对比 → 逐步替换。

### 🔶 变更主题应更单一
**当时的错误：** V7.2.10 同时包含联机框架、战斗通报 UI、囚徒回血数值修正三类变更，回滚心智负担重。

**改进方向：** 大版本尽量单一主题。如果"顺带修"，在迭代说明里独立小节。

### 🔶 没有"用户访谈"过程
**当时的错误：** 12 个版本的需求全来自自己测试 + 朋友小范围反馈。

**改进方向：** 下一项目在 V7.0 之前做 3–5 个目标用户访谈，定量+定性结合。

### 🔶 AI 编码边界没从 Day 1 定义清楚
**当时的错误：** 从 V7.1.1 开始用 AI，但没写 `AI_USAGE_POLICY.md`。部分引擎实现细节我自己讲不清楚"为什么这么写"。

**改进方向：** 下一项目 Day 1 写 AI 边界，每个模块标注归属。

## 3. 停止（Stop）

### ❌ 不要用"反正别人也会遇到"掩盖问题
**当时的错误：** V7.2.6 把环境阻断写进 PASS 备注，没有独立标记 PENDING。

**V7.2.7 已纠正：** `Browser URL Entry Runtime = PENDING_ENVIRONMENT_GATE`。

**结论：** 停止混用 PASS 和 PENDING。

### ❌ 不要低估"老代码迁移"
**当时的错误：** Engine Core 化预估 2 周，实际 10+ 周。

**结论：** 停止乐观估计迁移耗时。对老代码保持敬畏。

## 4. 开始（Start）

### 🆕 阶段门禁脚本化
**现状：** 靠人工跑回归 + 人工看 JSON 报告。

**方向：** 写 `gate_check.js`，自动跑全量并按 PASS/FAIL/PENDING 输出结论。

### 🆕 用户访谈前置
**现状：** V7.0.2 之前无用户数据。

**方向：** 立项第一周做 3–5 个目标用户访谈。

### 🆕 AI 协作从 Day 1 写边界
**现状：** V7.1.1 之后才开始反思。

**方向：** Project kickoff 时同时提交 `AI_USAGE_POLICY.md`。

### 🆕 多渠道分发
**现状：** 目前仅 GitHub Pages。

**方向：** itch.io 上架 + 网盘备用（已将方案写入 `docs/07-部署与发行.md`）。
