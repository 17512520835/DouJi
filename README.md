## 📌 项目定位

这是一份**用于留学申请公开评估的数字桌游作品集**，不是一份"游戏安装包"或"商业发行物"。

我（项目主导者）把它放进 GitHub 的目的是：

> 让招生官 / 面试官能在 5 分钟内看完「我在这个项目里做了什么 PM 工作、做了什么技术决策、走了哪些弯路」。代码只是这些决策的**物证**。

如果你想直接玩游戏，请看下一节「在线试玩」。
如果你想评估 PM / 设计 / 工程能力，请直接跳到「能力展示」与「迭代时间线」。

## 🎯 能力展示（PM 视角）

本项目完整走过了 **V7.0.2 → V7.2.10** 共 12 个公开版本、6 个交付阶段（Phase 1–6）。每一阶段都是一份独立的「需求→设计→实现→验证」PM 闭环。

| 能力维度 | 在本项目中的体现 | 证据位置 |
|---------|---------------|---------|
| **项目统筹** | 把"地图缩域"这一模糊需求拆解为 3 个交付阶段（Map Core / Phase2 / Hotfix），跨 5 个版本渐进达成 | `docs/03-迭代路线图.md` § 阶段 4 |
| **需求规划** | 每次修复都从用户实际对局问题出发，而不是凭空加功能 | `docs/02-需求规划.md` |
| **进度管控** | 22 份 JSON 验证报告构成可机读证据链；任何"做完"都必须有 PASS 数 | `tests/reports/*.json` |
| **迭代优化** | 27 篇迭代说明 MD 全部保留，每篇都是「现象→根因→修复→验证」四段式 | `docs/iteration-archive/` |
| **架构决策** | Phase 4 把"游戏核心"封箱为不可变模块，UI 仅通过 Observation 获取状态 | `docs/05-架构契约.md` |
| **跨阶段一致性** | Phase 6 Golden Master：同一 seed 跨 v714 / v721 双版本跑 163 步，玩家可观察状态 100% 一致 | `docs/03-迭代路线图.md` § 阶段 6 |
| **质量门禁设计** | 不允许"虚报 PASS"——浏览器受管理员策略阻断就如实标 PENDING，不伪造通过 | `docs/04-问题复盘.md` § 3 |

完整的能力维度和反思见 [`docs/01-项目概述.md`](docs/01-项目概述.md)。

## 🧰 技术栈

| 层 | 选型 | 原因 |
|---|------|------|
| 游戏核心 | 纯 JavaScript（无框架） | 单文件可直接嵌入 HTML，便于 GitHub Pages 静态部署 |
| 引擎封装 | UMD / Facade + WeakMap | 让 UI 只能通过 Observation 获取状态，杜绝绕过 |
| 确定性 | 自研确定性核心 | 同一 seed + 同一动作序列 → 100% 相同状态（已跨版本验证） |
| 联机 | Node.js HTTP + 自研 WebSocket | 零 npm 依赖，可独立部署在任何 Node 18+ 主机 |
| 客户端 | 原生 HTML + 内联 CSS/JS | 单文件 7.7MB 即可玩，无构建步骤 |
| 美术 | WebP | 体积小、浏览器原生支持 |

## 🚀 快速开始

### 仅试玩（不需 Node / 不需任何安装）

1. 进入 [GitHub Pages 链接](#-在线试玩) 直接玩
2. 或下载本仓库 → 双击 `index.html` 用浏览器打开

### 本地联机（需要 Node.js 18+）

```bash
git clone https://github.com/17512520835/DouJi.git
cd DouJi/src
# Windows: 双击 启动联机服务器.bat
# macOS / Linux: ./启动联机服务器.sh
```

主机访问 `http://localhost:8787` 创建房间，好友访问 `http://你的局域网IP:8787` 加入。

> 局域网联机首次需放行 8787 端口防火墙；公网/异地可看 [`docs/07-部署与发行.md`](docs/07-部署与发行.md)。

## 🤝 AI 辅助边界声明（面试必读）

> 这是我作为项目主导者，**主动声明的 AI 使用边界**。本声明不是免责声明，是我对作品集透明度的承诺。

**AI 协助的部分：**
- 引擎 bundle 的部分实现细节、调试适配器
- 联机服务器协议编码、回归脚本脚手架
- 部分文档的语言润色

**AI 没有参与的部分：**
- 12 个版本的需求决策（每一版为什么做这一件事）
- 27 篇迭代说明里的"现象→根因"分析（每篇都对应一次真实对局）
- 22 份 JSON 验证报告的实际运行与判读
- 架构决策（Phase 4 封箱、Observation 边界、Deterministic Core 路线）
- 阶段门禁设计（什么算 PASS / 什么必须如实标 PENDING）

**透明性承诺：**
- 27 篇迭代 MD 全部保留原始时间戳与决策脉络
- 我在面试中能逐条讲清楚每版决策背后的取舍
- 任何"AI 生成"代码我都标注了来源；如果我说不出来源，我会说"我需要回去查"

详细边界见 [`docs/06-AI辅助边界声明.md`](docs/06-AI辅助边界声明.md)。
